# שליחה קלה - BT

שליחה וקבלה של קבצים בבלוטוס ב-Windows 10 ו-11, בקליק ימני. קוד פתוח, ברישיון MIT.

התוכנה פותרת שתי בעיות נפוצות:

- **שליחה:** פריט ברמה העליונה של תפריט הקליק הימני (גם ב-Windows 11, בלי "הצג אפשרויות נוספות") לכל קובץ ותיקייה.
- **קבלה:** במחשבים רבים לא ניתן לקבל קבצים מטלפון, כי Windows מפעיל שירות קבלה רק כשחלון "קבל קובץ" פתוח. התוכנה מפעילה שירות קבלה משלה ברקע.

## הורדה והתקנה

1. הורד את `SendEasyBT-Setup.exe` מעמוד [Releases](../../releases/latest).
2. הפעל אותו. ההתקנה היא למשתמש הנוכחי ולא דורשת הרשאות מנהל, חוץ מהצעד האופציונלי של Windows 11 (ראה למטה).
3. אם .NET 8 Desktop Runtime כבר מותקן, המתקין מדלג עליו. אם לא, הוא מוריד ומתקין אותו (כ-58MB, יבקש אישור מנהל).

### פריט ברמה העליונה ב-Windows 11
כדי שהפריט יופיע ברמה העליונה, Windows דורש חבילה חתומה. התוכנה משתמשת בתעודה עצמית (בלי תעודה בתשלום), ולכן ההתקנה מוסיפה אותה לרשימת "אנשים מהימנים" של המחשב. זה הצעד היחיד שמבקש אישור מנהל, והוא אופציונלי: בלי זה הפריט יופיע תחת "הצג אפשרויות נוספות". ב-Windows 10 לא צריך אותו.

## שימוש

### שליחה
- **קליק ימני** על קובץ, כמה קבצים או תיקייה, ובחירת "שליחה קלה - BT". נפתח חלון עם המכשירים.
- **גרירה** של קבצים לחלון השליחה.
- **קיצור מקשים:** ברירת מחדל Ctrl+Alt+B שולח את הקבצים שנבחרו בסייר.
- **שליחת טקסט או קישור:** Ctrl+Alt+V שולח את תוכן הלוח כקובץ טקסט.
- **מכשירים מועדפים:** כוכב ★ ליד מכשיר. לכל מועדף אפשר להגדיר קיצור מקשים שישלח אליו ישירות, בלי חלון בחירה, ולבחור מכשיר ברירת מחדל.
- **ביטול:** כפתור "בטל שליחה" עוצר את השליחה, גם בין הניסיונות החוזרים.

מכשירים מוצמדים מוצגים ברשימה. מכשירים קרובים שלא הוצמדו מוסתרים בתפריט נפתח, וההצמדה נעשית אוטומטית בשליחה הראשונה.

### תיקיות
תיקייה או כמה פריטים נארזים לקובץ ZIP עם סימון מזהה. כשהמקבל גם מריץ את התוכנה, הקובץ נפתח אוטומטית לתיקייה. בהגדרות אפשר לבחור לפתוח כל ZIP שמגיע, ולמחוק את ה-ZIP אחרי הפתיחה.

### קבלה
- התוכנה רצה במגש המערכת, ומקבלת קבצים מכל מכשיר.
- **מצבי קבלה:** שאל תמיד, אוטומטי ממכשירים מוצמדים (ברירת מחדל), אוטומטי מכולם.
- חלון קטן בפינה מציג התקדמות ומהירות, ומאפשר ביטול.
- התיקייה ברירת המחדל: `Downloads\שליחה קלה`.

### היסטוריה
חלון שמראה מה נשלח ומה התקבל, עם פתיחת הקובץ והצגתו בסייר.

### כשהמכשיר רחוק או כבוי
התוכנה מנסה שלוש פעמים, ואז מציגה כפתור "נסה שוב".

## מגבלות ידועות

- הטלפון מחליט אילו סוגי קבצים לקבל. באנדרואיד, קבצים עם סיומת לא מוכרת נדחים, ולכן התוכנה עוטפת אותם אוטומטית בקובץ ZIP ושולחת שוב.
- אייפון אינו תומך בקבלת קבצים בבלוטוס בפרוטוקול הזה.
- הצ'אט בחלון התוכנה הוא כרגע הדגמה בלבד, ועדיין לא מחובר לבלוטוס. החיבור האמיתי מתוכנן עם אפליקציית אנדרואיד נלווית.
- נבדק עם Windows 11 ועם טלפון אחד (Qin 1s+). דיווחים על מכשירים אחרים יתקבלו בברכה ב-Issues.

## פרטים טכניים

### מבנה
```
src/SendEasy.Core   ליבה: OBEX, שרת וקליינט, אריזה ופתיחה של ZIP, הגדרות, היסטוריה
src/SendEasy.App    אפליקציית WPF (WPF-UI), מגש מערכת, חלונות, אינטגרציה עם Windows
tests/              בדיקות יחידה (פתיחת ZIP בטוחה, שמות קבצים)
build/              סקריפטי בנייה, מתקין (Inno Setup), מניפסט החבילה
```
.NET 8, `net8.0-windows10.0.19041.0`, WPF עם [WPF-UI](https://github.com/lepoco/wpfui), ו-WinRT לבלוטוס (`Windows.Devices.Bluetooth`).

### פרוטוקול
אין ב-Windows API ל-OBEX, ולכן מומש בתוכנה לקוח ושרת OBEX Object Push (פרופיל OPP, UUID `0x1105`) מעל RFCOMM:

- **קבלה:** `RfcommServiceProvider` עם שירות `ObexObjectPush`, `StreamSocketListener` והגנה `BluetoothEncryptionAllowNullAuthentication`.
- **שליחה:** `GetRfcommServicesForIdAsync` וחיבור עם `BluetoothEncryptionWithAuthentication`.
- **פרטי תאימות עם אנדרואיד שנלמדו בניסוי:**
  - יש להחזיר את הכותרת `ConnectionID` (`0xCB`) מתשובת ה-CONNECT.
  - החבילה הראשונה של PUT מכילה רק כותרות (`Name`, `Length`), בלי `Type` ובלי `Body`. אחריה חבילות `Body`, והאחרונה (`0x82`) כוללת `EndOfBody`.
  - קוד `0xCF` או `0xC0` משמעותם סוג או סיומת שנדחו, ואז עוטפים ב-ZIP.

### אבטחה
פתיחת ZIP היא הנקודה הרגישה ביותר, ולכן `SafeExtractor` מגן מפני:
- Zip-slip וניסיונות יציאה מהתיקייה (`..`, נתיבים מוחלטים).
- שמות שמורים של Windows (`CON`, `NUL` ודומיהם) ו-Alternate Data Streams (`:`).
- פצצות ZIP: מגבלות על גודל כולל, מספר קבצים ויחס דחיסה.
- דריסת קבצים: אף פעם לא דורסים, בוחרים שם ייחודי.

קבצים שהתקבלו מסומנים ב-Mark of the Web (`Zone.Identifier`), כך ש-Windows מתייחס אליהם כקבצים שהורדו מהאינטרנט. כל הבדיקות בקובץ [ArchiveTests.cs](tests/SendEasy.Tests/ArchiveTests.cs).

### פריט בתפריט הקליק הימני של Windows 11
- פריט ברמה העליונה דורש `IExplorerCommand` בחבילת MSIX. התוכנה היא שרת COM מחוץ לתהליך (`ExeServer`) בתוך `SendEasyBT.exe` (מצב `-Embedding`).
- החבילה דלילה (sparse): היא רק מצהירה על ההרחבה ומצביעה על הקבצים בתיקיית ההתקנה (`Add-AppxPackage -ExternalLocation`).
- החבילה חתומה בתעודה עצמית (`CN=SendEasyBT`) שנוספת ל-`LocalMachine\TrustedPeople`.
- כגיבוי: פריט רגיסטרי קלאסי (HKCU) ו-"שלח אל".

### מנגנונים נוספים
- **מופע יחיד:** Mutex ו-named pipe. נתיבים שמגיעים בתוך 700ms מאוחדים לחלון אחד.
- **קיצורי מקשים:** `RegisterHotKey`.
- **בחירה בסייר:** `Shell.Application` עם גיבוי של Ctrl+C ללוח.

### בנייה מהמקור
דרישות: Windows, .NET 8 SDK.

```powershell
dotnet build src/SendEasy.App -c Release
dotnet test tests/SendEasy.Tests
```

בניית מתקין מלא (חבילה חתומה והמתקין):

```powershell
dotnet restore build/fetch/buildtools.csproj
dotnet restore build/fetch/innosetup.csproj
./build/build_release.ps1
```
הסקריפט יוצר מפתח חתימה עצמי בתיקייה `keys/` אם אין, ושם נשמר המפתח הפרטי. התיקייה מוחרגת מ-git. **אל תפרסם את המפתח הפרטי.**

### גרסאות אוטומטיות
תהליך GitHub Actions ([build.yml](.github/workflows/build.yml)) בונה ומפרסם גרסה חדשה רק כשהקוד משתנה (`src/`, `tests/`, `build/` או קובץ התהליך עצמו). שינויים ב-README או ברישיון לא מפעילים בנייה. מפתח החתימה נשמר כסוד של המאגר ואינו מופיע בקוד.
