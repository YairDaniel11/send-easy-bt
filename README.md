# שליחה קלה - BT

שליחה וקבלה של קבצים והודעות בבלוטוס בין Windows 10 ו-11 לטלפון, בקליק ימני. קוד פתוח, ברישיון MIT.

מלבד תוכנת Windows יש גם **אפליקציית אנדרואיד** נלווית (אנדרואיד 4.4 ומעלה, כולל מכשירי מקשים בלי מסך מגע). כשהאפליקציה מותקנת בטלפון, התוכנה מדברת איתה בפרוטוקול פרטי מעל RFCOMM ומקבלים:

- **כל סוג קובץ**, בלי עטיפה ב-ZIP.
- **בדיקת שלמות** SHA-256 לכל קובץ, ו**ביטול** באמצע העברה.
- **צ'אט טקסט**, **תמונות**, **הודעות קוליות** וקבצים מכל סוג בתוך הצ'אט (עד 100MB לקובץ מצורף; לקובץ גדול יותר משתמשים בשליחה הרגילה). אישורי מסירה וקריאה (וי וגם וי כפול) גם לתמונות ולהקלטות.
- **כמה שיחות נפרדות** עם אותו מכשיר: פתיחת "צ'אט חדש" בצד אחד פותחת אותו גם בצד השני, ואפשר לעבור בין השיחות מהתפריט.
- **שלושה סגנונות עיצוב לצ'אט**: ווטסאפ, גוגל צ'אט, וסגנון שלישי ללא בועות שבנוי לכתיבה ישירה בתוך השיחה ("טקסט פשוט" באפליקציה, כהה עם כותרת תכלת; "כתבן" ב-Windows, דף לבן). הבחירה בהגדרות ב-Windows ובתפריט הצ'אט באפליקציה.
- **עדכון גרסה:** שני הצדדים בודקים עדכון ברקע ומתריעים פעם אחת לכל גרסה חדשה. בתוכנה ההתראה היא חלון קטן אחד, במיקום שבחרת בהגדרות.
- **מצב כהה** בתוכנה ובאפליקציה, עם מתג בהגדרות. העיצוב זהה בבהיר ובכהה, ורק הצבעים משתנים.
- **ווידג'טים באפליקציה** למסך הבית: שליחת קובץ וצ'אט.
- **חיבור יציב לאפליקציה שרצה ברקע:** אם חיפוש השירות של Windows נכשל, התוכנה מתחברת ישירות לטלפון, כך שהשליחה דרך האפליקציה (בלי בקשת אישור בטלפון) עובדת גם כשהאפליקציה לא פתוחה על המסך.

בלי האפליקציה בטלפון, השליחה נעשית כמקודם ב-OBEX Object Push רגיל.

התוכנה פותרת שתי בעיות נפוצות:

- **שליחה:** פריט ברמה העליונה של תפריט הקליק הימני (גם ב-Windows 11, בלי "הצג אפשרויות נוספות") לכל קובץ ותיקייה.
- **קבלה:** במחשבים רבים לא ניתן לקבל קבצים מטלפון, כי Windows מפעיל שירות קבלה רק כשחלון "קבל קובץ" פתוח. התוכנה מפעילה שירות קבלה משלה ברקע.

## הורדה והתקנה

1. הורד את `SendEasyBT-Setup-<גרסה>.exe` מעמוד [Releases](../../releases/latest)
2. הפעל אותו. ההתקנה היא למשתמש הנוכחי ולא דורשת הרשאות מנהל, חוץ משני מקרים: התקנת .NET 8 אם הוא חסר (שלב 3), והצעד האופציונלי של Windows 11 (ראה למטה).
3. אם .NET 8 Desktop Runtime כבר מותקן, המתקין מדלג עליו. אם לא, הוא מוריד ומתקין אותו (כ-58MB, יבקש אישור מנהל).
4. בהתקנה אפשר לסמן (אופציונלי) קיצורי דרך בשולחן העבודה: אחד לשליחת קבצים ואחד לחלון הצ'אט. קיצור הצ'אט עובד גם כשהתוכנה כבר רצה ברקע.

### פריט ברמה העליונה ב-Windows 11
כדי שהפריט יופיע ברמה העליונה, Windows דורש חבילה חתומה. התוכנה משתמשת בתעודה עצמית (בלי תעודה בתשלום), ולכן ההתקנה מוסיפה אותה לרשימת "אנשים מהימנים" של המחשב. הצעד הזה מבקש אישור מנהל בהתקנה הראשונה בלבד (בעדכונים התעודה כבר מהימנה), והוא אופציונלי: בלי זה הפריט יופיע תחת "הצג אפשרויות נוספות". בהסרת התוכנה התעודה מוסרת, וגם זה מבקש אישור מנהל. ב-Windows 10 לא צריך את הצעד הזה.

## אפליקציית אנדרואיד

### התקנה בטלפון
1. הורד את `SendEasyBT-<גרסה>.apk` מהגרסה האחרונה ב-[Releases](../../releases/latest). כל Release כולל את מתקין ה-Windows ואת ה-APK העדכני.
2. פתח את הקובץ בטלפון ואשר התקנה ממקור לא ידוע.
3. הפעל את האפליקציה ואשר את ההרשאות שהיא מבקשת.

### צימוד
צמד את הטלפון והמחשב בהגדרות הבלוטוס, פעם אחת, כרגיל. האפליקציה מציגה את המכשירים המצומדים. התוכנה במחשב צריכה לרוץ (מגש המערכת) כדי לקבל.

### שימוש
- **שליחה מהמחשב:** קליק ימני על קבצים ובחירת "שליחה קלה - BT (בלוטוס)", ובחירת הטלפון. התוכנה בודקת בעצמה אם האפליקציה מותקנת, ואם כן שולחת דרכה (בחלון ההתקדמות מופיע "דרך שליחה קלה במכשיר השני") כל סוג קובץ בלי ZIP.
- **שליחה מהטלפון:** באפליקציה בחר את המחשב, ואז "שלח קובץ". אפשר גם לשתף קבצים לאפליקציה מתוך אפליקציות אחרות ואז לבחור מכשיר.
- **צ'אט:** באפליקציה בחר את המחשב ואז "צ'אט". במחשב: "צ'אט" בתפריט המגש. אפשר לשלוח טקסט, תמונות, קבצים מכל סוג (עד 100MB) והודעות קוליות. לחיצה על תמונה פותחת אותה לצפייה (במחשב: בגודל מותאם לחלון). באפליקציה, לחיצה על קובץ שהתקבל פותחת את התיקייה שבה הוא נשמר. במחשב, קבצים שהתקבלו נשמרים בתיקיית הקבלה, ובסגנון "כתבן" לחיצה על קובץ בשיחה פותחת אותו.
- **הדבקה בצ'אט:** במחשב, Ctrl+V של תמונה (או של קובץ תמונה שהועתק) מצרף אותה להודעה. באפליקציה, "הדבק מהלוח" בתפריט הצ'אט מדביק טקסט או תמונה (בחלק מהמכשירים זה עדיין לא עובד).
- **טיוטות (באפליקציה):** הודעה שלא נשלחה אפשר לשמור כטיוטה, והיא תישלח יחד עם ההודעה הבאה לאותו מכשיר.
- **הקלטה:** בצ'אט, כפתור המיקרופון (בסגנון השלישי הוא אחד משלושת הכפתורים בתחתית, ובמחשב גם Ctrl+R או קליק ימני על כותרת השיחה). בזמן ההקלטה מופיעים פקדים: שלח (הכי שמאלי), השהה/המשך, בטל.
- **קבלה:** האפליקציה מקבלת ברקע כשהקבלה פעילה (תפריט > הגדרות > מתג "קבלת קבצים והודעות ברקע"). הקבצים נשמרים בתיקייה שמוצגת בהגדרות, תחת "קבצים".
- **הגדרות:** תפריט > הגדרות. מחולקות לנושאים: **כללי** (קבלה ברקע, התראה קבועה, מצב כהה), **הודעות וצ'אט** (התראה בעת קבלת הודעה, עיצוב הצ'אט, מחיקת שיחות), **קבצים** (תיקיית קבלה ותיקיית שמירה) ו**מכשירים** (שינוי שם מכשיר). הגדרה בלי תת-הגדרות היא מתג הדלקה וכיבוי. הגדרה עם תת-הגדרות היא שורה עם חץ שפותחת חלונית משלה (למשל "התראה בעת קבלת הודעה": התראה, צלצול, רטט והדלקת מסך). שינוי הגדרה לא סוגר את החלונית.
- **מצב כהה:** מתג בהגדרות. כל המסכים והחלונות, כולל "אודות", בצבעי האפליקציה.
- **ווידג'טים:** מוסיפים למסך הבית את "שלח קובץ" או "צ'אט". לחיצה פותחת בחירת מכשיר, ועם מכשיר מצומד אחד עוברת ישר לפעולה.
- **ההתראה הקבועה של הקבלה:** באנדרואיד 7 ומטה, כשההתראה מוסתרת בהגדרות היא נעלמת לגמרי (השירות ממשיך לרוץ בלי התראה). באנדרואיד 8 ומעלה מערכת ההפעלה מחייבת התראה לשירות כזה, ולכן ההגדרה הופכת אותה לשקטה וממוזערת, והאפליקציה מציעה לפתוח את הגדרות הערוץ במערכת כדי לכבות אותה שם.
- **דפדוף בצ'אט:** כשמדפדפים אחורה מופיע למטה במרכז כפתור עגול עם חץ למטה לחזרה להודעה האחרונה. במכשירי מקשים: מקש שמאלה מעביר אליו את הפוקוס, ואישור חוזר לסוף. השמעת הקלטה או הודעה חדשה כבר לא מקפיצות את מי שדפדף אחורה.

### מכשירי מקשים
האפליקציה בנויה גם לניווט בלי מסך מגע:

| מקש | פעולה |
|---|---|
| חצים | מעבר בין פריטים |
| אישור (מרכז החצים או Enter) | בחירה |
| מקש תפריט, מקש רך שמאלי או # | פתיחת תפריט אפשרויות (במסך קבצים: סיום הבחירה) |
| מקש רך ימני | חזרה או ביטול |
| חזרה | חזרה. במסך קבצים: תיקייה אחת למעלה. בשדה הודעה עם טקסט: מוחק תו |
| שמאלה (בשיחה, אחרי דפדוף אחורה) | פוקוס על כפתור "חזרה לסוף"; אישור חוזר להודעה האחרונה |

בזמן הקלטה: אישור משהה או ממשיך, תפריט שולח, חזרה או מקש רך ימני מבטלים.

**מקשי החיוג והניתוק אינם בשימוש.** במכשירי מקשים המערכת תופסת אותם לפני האפליקציה, ולכן לא ניתן להסתמך עליהם.

## שימוש בתוכנה

### הפעלה
התוכנה עולה אוטומטית עם Windows ורצה ברקע, כדי שהמחשב יוכל לקבל קבצים. האייקון שלה נמצא במגש המערכת ליד השעון (אם הוא לא מופיע, הוא מוסתר מתחת לחץ ^). לחיצה כפולה עליו פותחת חלון שליחה, וקליק ימני פותח את התפריט: שליחה, צ'אט, קבצים, תיקיית קבלה, הפעלה וכיבוי של הקבלה, הגדרות ויציאה. "אודות" נמצא בראש חלון ההגדרות.

**מעבר בין חלונות:** בחלונות השליחה, הצ'אט (בכותרת השיחה), הקבצים וההגדרות יש שורת כפתורים למעבר לשאר החלונות.

אחרי "יציאה" המחשב לא מקבל קבצים עד שהתוכנה נפתחת שוב: מתפריט התחל ("שליחה קלה - BT"), או בקליק ימני על קובץ ובחירת "שליחה קלה - BT (בלוטוס)". את ההפעלה האוטומטית אפשר לכבות בהגדרות Windows > אפליקציות > הפעלה, ואז המחשב יקבל קבצים רק כשהתוכנה פתוחה.

### שליחה
- **קליק ימני** על קובץ, כמה קבצים או תיקייה, ובחירת "שליחה קלה - BT (בלוטוס)". נפתח חלון עם המכשירים.
- **גרירה** של קבצים לחלון השליחה.
- **קיצור מקשים:** ברירת מחדל Ctrl+Alt+B שולח את הקבצים שנבחרו בסייר.
- **שליחת טקסט או קישור:** Ctrl+Alt+V שולח את תוכן הלוח כקובץ טקסט.
- **פתיחת הצ'אט:** קיצור מקשים אופציונלי (ברירת מחדל Ctrl+Alt+C, כבוי עד שמפעילים בהגדרות).
- **מכשירים מועדפים:** כוכב ★ ליד מכשיר. לכל מועדף אפשר להגדיר קיצור מקשים שישלח אליו ישירות, בלי חלון בחירה, ולבחור מכשיר ברירת מחדל.
- **כמה מכשירים בבת אחת:** מסמנים כמה מכשירים ולוחצים על הכפתור הראשי, שמציג את מספרם (למשל "שלח ל-3 מכשירים"). הקבצים נשלחים לכל מכשיר בתורו. הכפתור ➤ בשורת מכשיר שולח מיד רק אליו.
- **ביטול:** כפתור "בטל שליחה" עוצר את השליחה, גם בין הניסיונות החוזרים.
- **תור שליחה:** אם מתבצעת שליחה ובינתיים שולחים קובץ נוסף, הוא נכנס לרשימת המתנה ונשלח אוטומטית מיד אחרי שהקודמת מסתיימת. החלון מציג שהקובץ ממתין.
- **מיון לפי שימוש:** ברשימת המכשירים (בתוכנה ובאפליקציה) מופיעים קודם המכשירים ששלחת אליהם הכי הרבה, ובאופן שמתחשב גם בעדכניות: שימוש ישן נחשב פחות (חצי חיים של 30 יום). בתוכנה מועדפים ★ נשארים למעלה. הנתונים נשמרים מקומית בלבד (`%APPDATA%\SendEasyBT\usage.json`).

מכשירים מצומדים מוצגים ברשימה. מכשירים קרובים שלא צומדו מוסתרים בתפריט נפתח, והצימוד נעשה אוטומטית בשליחה הראשונה. אוזניות, דיבוריות ורמקולים לא מוצגים.

### תיקיות
תיקייה או כמה פריטים נארזים לקובץ ZIP עם סימון מזהה. כשהמקבל גם מריץ את התוכנה, הקובץ נפתח אוטומטית לתיקייה. בהגדרות אפשר לבחור לפתוח כל ZIP שמגיע, ולמחוק את ה-ZIP אחרי הפתיחה.

### קבלה
- התוכנה רצה במגש המערכת, ומקבלת קבצים מכל מכשיר.
- **מצבי קבלה:** שאל תמיד, אוטומטי ממכשירים מצומדים (ברירת מחדל), אוטומטי מכולם.
- חלון קטן מציג התקדמות ומהירות, ומאפשר ביטול. מיקום החלונות הקטנים (הודעה, קבלה, עדכון) נבחר בהגדרות: למטה או למעלה, מימין, במרכז או משמאל.
- התיקייה ברירת המחדל: `Downloads\שליחה קלה`.

### קבצים
חלון שמראה מה נשלח ומה התקבל (תפריט המגש, "קבצים"). אפשר לסנן לפי מכשיר, כיוון (התקבלו, נשלחו, נכשלו) וסוג קובץ, לחפש לפי שם, לפתוח את הקובץ, להציג אותו בסייר או להסיר אותו מהרשימה (הקובץ עצמו לא נמחק). הקשה כפולה על שורה פותחת את התיקייה של הקובץ ומסמנת אותו. קובץ שנמחק מהדיסק מסומן באדום "נמחק" מתחת לשם (ואז ההקשה הכפולה פותחת את התיקייה שבה היה).

### הגדרות
חלון ההגדרות אינו חוסם את שאר החלונות, והשינויים נשמרים בלחיצה על "שמור". הוא מסודר לפי נושאים: מראה, קבלת קבצים, תיקיית קבלה, ארכיונים (ZIP), קיצורי מקשים, מכשירים מועדפים, צ'אט והודעות, עדכונים, אפליקציית אנדרואיד וניהול התוכנה.
- **מצב כהה:** מתג שחל מיד על כל החלונות, גם לפני "שמור" (ביטול מחזיר את המצב הקודם).
- **ניהול התוכנה:** "יציאה מהתוכנה" סוגרת הכול, כולל הקבלה והקיצורים ברקע. "הסרת התוכנה" מפעילה את מסיר ההתקנה (אחרי אישור) ויוצאת.
- שגיאות מוצגות בעברית.

### כשהמכשיר רחוק או כבוי
התוכנה מנסה כמה פעמים, ואז מציגה כפתור "נסה שוב". ההודעה מבדילה בין חיבור שלא הצליח (רחוק, כבוי או עסוק) לבין חיבור שנקטע באמצע השליחה.

### כשהאפליקציה בטלפון לא עונה
התוכנה עוברת לשליחה בבלוטוס רגיל (והטלפון מבקש אישור קבלה), ומציגה מתחת לסטטוס את הסיבה בקצרה. הסיבות נשמרות גם בקובץ `%LOCALAPPDATA%\SendEasyBT\peer.log`, לעזרה באבחון.

## מגבלות ידועות

- בלי אפליקציית האנדרואיד, הטלפון מחליט אילו סוגי קבצים לקבל. קבצים עם סיומת לא מוכרת נדחים, ולכן התוכנה עוטפת אותם אוטומטית בקובץ ZIP ושולחת שוב.
- צ'אט, הודעות קוליות ושליחה בלי ZIP דורשים את אפליקציית האנדרואיד. אייפון אינו נתמך (אין בו קבלת קבצים בבלוטוס בפרוטוקול הזה).
- בלוטוס אמיתי נבדק רק עם Qin 1s+ ו-Windows 11. דיווחים על מכשירים אחרים יתקבלו בברכה ב-Issues.
- ה-APK הוא גרסת debug, חתומה במפתח debug ציבורי קבוע שנמצא במאגר. לכן עדכון של האפליקציה מתקין מעל הקיימת בלי הסרה. (גרסאות ישנות שנחתמו במפתח אחר דורשות הסרה והתקנה מחדש פעם אחת.)
- בבחירת כמה קבצים לשליחה בטלפון חדש, בורר הקבצים של מערכת אנדרואיד מציג "פתח" ולא "שלח". זה כיתוב של המערכת, ולא ניתן לשנות אותו מהאפליקציה.
- הקלטה במחשב דורשת הרשאת מיקרופון ב-Windows: הגדרות > פרטיות > מיקרופון, כולל "אפליקציות שולחן עבודה".
- הצפנה מעבר לזו של הבלוטוס עצמו מתוכננת לגרסה 2 של הפרוטוקול.

## פרטים טכניים

### מבנה
```

src/SendEasy.App    אפליקציית WPF (WPF-UI), מגש מערכת, חלונות (כולל צ'אט והקלטה ושורת מעבר בין חלונות), מצב כהה, אינטגרציה עם Windows
android/            אפליקציית אנדרואיד (Java, Gradle, minSdk 19), כולל ווידג'טים למסך הבית
tests/              בדיקות יחידה (הפרוטוקול הפרטי, פתיחת ZIP בטוחה, שמות קבצים)
build/              סקריפטי בנייה, מתקין (Inno Setup), מניפסט החבילה

```
.NET 8, `net8.0-windows10.0.19041.0`, WPF עם [WPF-UI](https://github.com/lepoco/wpfui), ו-WinRT לבלוטוס (`Windows.Devices.Bluetooth`).

### פרוטוקול פרטי (Windows - אנדרואיד)
מסגרות בינאריות מעל RFCOMM עם UUID ייעודי: HELLO, הודעות טקסט עם אישור, העברת קבצים בחלקים עם SHA-256 בסיום (הקובץ מתפרסם רק אחרי שהבדיקה עברה), ביטול, ו-PING לזיהוי חיבור מת. הפירוט המלא ב-[PROTOCOL.md](PROTOCOL.md). הצפנה נוספת מתוכננת לגרסה 2.

### פרוטוקול OBEX
אין ב-Windows API ל-OBEX, ולכן מומש בתוכנה לקוח ושרת OBEX Object Push (פרופיל OPP, UUID `0x1105`) מעל RFCOMM:

- **קבלה:** `RfcommServiceProvider` עם שירות `ObexObjectPush`, `StreamSocketListener` והגנה `BluetoothEncryptionAllowNullAuthentication`.
- **שליחה:** `GetRfcommServicesForIdAsync` וחיבור עם `BluetoothEncryptionWithAuthentication`.
- **פרטי תאימות עם אנדרואיד שנלמדו בניסוי:**
  - יש להחזיר את הכותרת `ConnectionID` (`0xCB`) מתשובת ה-CONNECT.
  - החבילה הראשונה של PUT מכילה רק כותרות (`Name`, `Length`), בלי `Type` ובלי `Body`. אחריה חבילות `Body`, והאחרונה (`0x82`) כוללת `EndOfBody`.
  - קוד `0xCF` או `0xC0` משמעותם סוג או סיומת שנדחו, ואז עוטפים ב-ZIP.

### אבטחה
פתיחת ZIP היא הנקודה הרגישה ביותר, ולכן `SafeExtractor` מגן מפני:
- Zip-slip וניסיונות יציאה מהתיקייה (`..`, נתיבים מוחלטים).
- שמות שמורים של Windows (`CON`, `NUL` ודומיהם) ו-Alternate Data Streams (`:`).
- פצצות ZIP: מגבלות על גודל כולל, מספר קבצים ויחס דחיסה.
- דריסת קבצים: אף פעם לא דורסים, בוחרים שם ייחודי.

קבצים שהתקבלו מסומנים ב-Mark of the Web (`Zone.Identifier`), כך ש-Windows מתייחס אליהם כקבצים שהורדו מהאינטרנט. כל הבדיקות בקובץ [ArchiveTests.cs](tests/SendEasy.Tests/ArchiveTests.cs).

### פריט בתפריט הקליק הימני של Windows 11
- פריט ברמה העליונה דורש `IExplorerCommand` בחבילת MSIX. התוכנה היא שרת COM מחוץ לתהליך (`ExeServer`) בתוך `SendEasyBT.exe` (מצב `-Embedding`).
- החבילה דלילה (sparse): היא רק מצהירה על ההרחבה ומצביעה על הקבצים בתיקיית ההתקנה (`Add-AppxPackage -ExternalLocation`).
- החבילה חתומה בתעודה עצמית (`CN=SendEasyBT`) שנוספת ל-`LocalMachine\TrustedPeople`.
- כגיבוי: פריט רגיסטרי קלאסי (HKCU) ו-"שלח אל".

### מנגנונים נוספים
- **מופע יחיד:** Mutex ו-named pipe. נתיבים שמגיעים בתוך 700ms מאוחדים לחלון אחד.
- **קיצורי מקשים:** `RegisterHotKey`.
- **בחירה בסייר:** `Shell.Application` עם גיבוי של Ctrl+C ללוח. בשולחן העבודה התוכנה ממתינה לשחרור מקשי הקיצור לפני ההעתקה, כדי ש-Ctrl+C לא יתפרש כשילוב אחר.
- **בנייה מקומית:** מספר הגרסה נלקח מהתג האחרון בגיטאב (`git fetch --tags` לפני הבנייה), כך שגרסת בדיקה לא מציגה "עדכון זמין" סתם.

### בנייה מהמקור
דרישות: Windows, .NET 8 SDK.

```powershell
dotnet build src/SendEasy.App -c Release
dotnet test tests/SendEasy.Tests
```

בניית מתקין מלא (חבילה חתומה והמתקין):

```powershell
dotnet restore build/fetch/buildtools.csproj
dotnet restore build/fetch/innosetup.csproj
./build/build_release.ps1
```
הסקריפט יוצר מפתח חתימה עצמי בתיקייה `keys/` אם אין, ושם נשמר המפתח הפרטי. התיקייה מוחרגת מ-git. **אל תפרסם את המפתח הפרטי.**

בניית אפליקציית האנדרואיד: JDK 17, Android SDK ו-Gradle 8.7.

```
cd android
gradle assembleDebug
```
ה-APK נוצר ב-`android/app/build/outputs/apk/debug/`.

### גרסאות אוטומטיות
תהליך GitHub Actions אחד ([build.yml](.github/workflows/build.yml)) רץ רק כשהקוד משתנה (`src/`, `tests/`, `build/`, `android/` או קובץ התהליך). שינויים ב-README או ברישיון לא מפעילים בנייה. הוא מריץ בדיקות, בונה את מתקין ה-Windows ואת ה-APK, ומפרסם Release אחד בתגית `v0.1.N` עם שני הקבצים (`SendEasyBT-Setup-<גרסה>.exe` ו-`SendEasyBT-<גרסה>.apk`, כשמספר הגרסה כלול בשם הקובץ). אם קוד האפליקציה לא השתנה, ה-APK הקיים עובר לגרסה החדשה כמו שהוא, עם מספר הגרסה שלו (הוא רשום בהערות ה-Release בשורה `android-version`), כדי שלא תופיע בטלפון התראת עדכון סתם. אם אחד מהם נכשל, לא מתפרסם Release. מפתח החתימה של ה-Windows נשמר כסוד של המאגר ואינו מופיע בקוד. ה-APK נחתם במפתח ה-debug הציבורי שבמאגר.
