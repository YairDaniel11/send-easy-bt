# שליחה קלה - BT

שליחה וקבלה של קבצים והודעות בבלוטוס בין Windows 10 ו-11 לטלפון, בקליק ימני. קוד פתוח, ברישיון MIT.

מלבד תוכנת Windows יש גם **אפליקציית אנדרואיד** נלווית (אנדרואיד 4.4 ומעלה, כולל מכשירי מקשים בלי מסך מגע). כשהאפליקציה מותקנת בטלפון, התוכנה מדברת איתה בפרוטוקול פרטי מעל RFCOMM ומקבלים:

- **כל סוג קובץ**, בלי עטיפה ב-ZIP.
- **בדיקת שלמות** SHA-256 לכל קובץ, ו**ביטול** באמצע העברה.
- **צ'אט טקסט**, **הודעות קוליות** וקבצים בתוך הצ'אט.
- **שני סגנונות עיצוב לצ'אט**, ווטסאפ וגוגל צ'אט. הבחירה בהגדרות ב-Windows ובתפריט באפליקציה.

בלי האפליקציה בטלפון, השליחה נעשית כמקודם ב-OBEX Object Push רגיל.

התוכנה פותרת שתי בעיות נפוצות:

- **שליחה:** פריט ברמה העליונה של תפריט הקליק הימני (גם ב-Windows 11, בלי "הצג אפשרויות נוספות") לכל קובץ ותיקייה.
- **קבלה:** במחשבים רבים לא ניתן לקבל קבצים מטלפון, כי Windows מפעיל שירות קבלה רק כשחלון "קבל קובץ" פתוח. התוכנה מפעילה שירות קבלה משלה ברקע.

## הורדה והתקנה

1. הורד את `SendEasyBT-Setup.exe` מעמוד [Releases](../../releases/latest), או ישירות מהקישור הקבוע: https://github.com/YairDaniel11/send-easy-bt/releases/latest/download/SendEasyBT-Setup.exe
2. הפעל אותו. ההתקנה היא למשתמש הנוכחי ולא דורשת הרשאות מנהל, חוץ מהצעד האופציונלי של Windows 11 (ראה למטה).
3. אם .NET 8 Desktop Runtime כבר מותקן, המתקין מדלג עליו. אם לא, הוא מוריד ומתקין אותו (כ-58MB, יבקש אישור מנהל).

### פריט ברמה העליונה ב-Windows 11
כדי שהפריט יופיע ברמה העליונה, Windows דורש חבילה חתומה. התוכנה משתמשת בתעודה עצמית (בלי תעודה בתשלום), ולכן ההתקנה מוסיפה אותה לרשימת "אנשים מהימנים" של המחשב. זה הצעד היחיד שמבקש אישור מנהל, והוא אופציונלי: בלי זה הפריט יופיע תחת "הצג אפשרויות נוספות". ב-Windows 10 לא צריך אותו.

## אפליקציית אנדרואיד

### התקנה בטלפון
1. הורד את `SendEasyBT.apk` מהגרסה האחרונה ב-[Releases](../../releases/latest), או ישירות מהקישור הקבוע: https://github.com/YairDaniel11/send-easy-bt/releases/latest/download/SendEasyBT.apk . כל גרסה כוללת את מתקין ה-Windows ואת ה-APK, באותו מספר גרסה.
2. פתח את הקובץ בטלפון ואשר התקנה ממקור לא ידוע.
3. הפעל את האפליקציה ואשר את ההרשאות שהיא מבקשת.

### צימוד
צמד את הטלפון והמחשב בהגדרות הבלוטוס, פעם אחת, כרגיל. האפליקציה מציגה את המכשירים המצומדים. התוכנה במחשב צריכה לרוץ (מגש המערכת) כדי לקבל.

### שימוש
- **שליחה מהמחשב:** קליק ימני על קבצים ובחירת "שליחה קלה - BT", ובחירת הטלפון. התוכנה בודקת בעצמה אם האפליקציה מותקנת, ואם כן שולחת דרכה (בחלון ההתקדמות מופיע "דרך האפליקציה") כל סוג קובץ בלי ZIP.
- **שליחה מהטלפון:** באפליקציה בחר את המחשב, ואז "שלח קובץ". אפשר גם לשתף קבצים לאפליקציה מתוך אפליקציות אחרות ואז לבחור מכשיר.
- **צ'אט:** באפליקציה בחר את המחשב ואז "צ'אט". במחשב: "צ'אט" בתפריט המגש. אפשר לשלוח טקסט, קבצים והודעות קוליות.
- **הקלטה:** בצ'אט, תפריט > "הקלט הודעה קולית", ושליחה בסיום. בטלפון הקלטה נשלחת באישור וניתנת לביטול. במחשב לוחצים על כפתור המיקרופון בחלון הצ'אט ואז על ➤ לשליחה.
- **קבלה:** האפליקציה מקבלת ברקע כשהקבלה פעילה (תפריט > "הפעל / כבה קבלה"). הקבצים נשמרים בתיקייה שמוצגת בתפריט > "איפה נשמרים הקבצים".

### מכשירי מקשים
האפליקציה בנויה גם לניווט בלי מסך מגע:

| מקש | פעולה |
|---|---|
| חצים | מעבר בין פריטים |
| אישור (מרכז החצים או Enter) | בחירה |
| מקש תפריט, מקש רך שמאלי או # | פתיחת תפריט אפשרויות (במסך קבצים: סיום הבחירה) |
| מקש רך ימני | חזרה או ביטול |
| חזרה | חזרה. במסך קבצים: תיקייה אחת למעלה. בשדה הודעה עם טקסט: מוחק תו |

בזמן הקלטה: אישור או תפריט שולחים, חזרה או מקש רך ימני מבטלים.

**מקשי החיוג והניתוק אינם בשימוש.** במכשירי מקשים המערכת תופסת אותם לפני האפליקציה, ולכן לא ניתן להסתמך עליהם.

## שימוש בתוכנה

### שליחה
- **קליק ימני** על קובץ, כמה קבצים או תיקייה, ובחירת "שליחה קלה - BT". נפתח חלון עם המכשירים.
- **גרירה** של קבצים לחלון השליחה.
- **קיצור מקשים:** ברירת מחדל Ctrl+Alt+B שולח את הקבצים שנבחרו בסייר.
- **שליחת טקסט או קישור:** Ctrl+Alt+V שולח את תוכן הלוח כקובץ טקסט.
- **מכשירים מועדפים:** כוכב ★ ליד מכשיר. לכל מועדף אפשר להגדיר קיצור מקשים שישלח אליו ישירות, בלי חלון בחירה, ולבחור מכשיר ברירת מחדל.
- **ביטול:** כפתור "בטל שליחה" עוצר את השליחה, גם בין הניסיונות החוזרים.

מכשירים מוצמדים מוצגים ברשימה. מכשירים קרובים שלא הוצמדו מוסתרים בתפריט נפתח, וההצמדה נעשית אוטומטית בשליחה הראשונה.

### תיקיות
תיקייה או כמה פריטים נארזים לקובץ ZIP עם סימון מזהה. כשהמקבל גם מריץ את התוכנה, הקובץ נפתח אוטומטית לתיקייה. בהגדרות אפשר לבחור לפתוח כל ZIP שמגיע, ולמחוק את ה-ZIP אחרי הפתיחה.

### קבלה
- התוכנה רצה במגש המערכת, ומקבלת קבצים מכל מכשיר.
- **מצבי קבלה:** שאל תמיד, אוטומטי ממכשירים מוצמדים (ברירת מחדל), אוטומטי מכולם.
- חלון קטן בפינה מציג התקדמות ומהירות, ומאפשר ביטול.
- התיקייה ברירת המחדל: `Downloads\שליחה קלה`.

### היסטוריה
חלון שמראה מה נשלח ומה התקבל, עם פתיחת הקובץ והצגתו בסייר.

### כשהמכשיר רחוק או כבוי
התוכנה מנסה שלוש פעמים, ואז מציגה כפתור "נסה שוב".

## מגבלות ידועות

- בלי אפליקציית האנדרואיד, הטלפון מחליט אילו סוגי קבצים לקבל. קבצים עם סיומת לא מוכרת נדחים, ולכן התוכנה עוטפת אותם אוטומטית בקובץ ZIP ושולחת שוב.
- צ'אט, הודעות קוליות ושליחה בלי ZIP דורשים את אפליקציית האנדרואיד. אייפון אינו נתמך (אין בו קבלת קבצים בבלוטוס בפרוטוקול הזה).
- בלוטוס אמיתי נבדק רק עם Qin 1s+ ו-Windows 11. דיווחים על מכשירים אחרים יתקבלו בברכה ב-Issues.
- ה-APK חתום כרגע במפתח debug שמשתנה בין בניות, ולכן עדכון של האפליקציה דורש הסרה והתקנה מחדש. זה יפסיק להיות נכון כשיוגדר מפתח קבוע.
- הקלטה במחשב דורשת הרשאת מיקרופון ב-Windows: הגדרות > פרטיות > מיקרופון, כולל "אפליקציות שולחן עבודה".
- הצפנה מעבר לזו של הבלוטוס עצמו מתוכננת לגרסה 2 של הפרוטוקול.

## פרטים טכניים

### מבנה
```
src/SendEasy.Core   ליבה: OBEX, הפרוטוקול הפרטי (PeerSession, PeerServer, PeerClient), לוג צ'אט, אריזה ופתיחה של ZIP, הגדרות, היסטוריה
src/SendEasy.App    אפליקציית WPF (WPF-UI), מגש מערכת, חלונות (כולל צ'אט והקלטה), אינטגרציה עם Windows
android/            אפליקציית אנדרואיד (Java, Gradle, minSdk 19)
tests/              בדיקות יחידה (פתיחת ZIP בטוחה, שמות קבצים)
build/              סקריפטי בנייה, מתקין (Inno Setup), מניפסט החבילה
PROTOCOL.md         מפרט הפרוטוקול הפרטי בין Windows לאנדרואיד
```
.NET 8, `net8.0-windows10.0.19041.0`, WPF עם [WPF-UI](https://github.com/lepoco/wpfui), ו-WinRT לבלוטוס (`Windows.Devices.Bluetooth`).

### פרוטוקול פרטי (Windows - אנדרואיד)
מסגרות בינאריות מעל RFCOMM עם UUID ייעודי: HELLO, הודעות טקסט עם אישור, העברת קבצים בחלקים עם SHA-256 בסיום (הקובץ מתפרסם רק אחרי שהבדיקה עברה), ביטול, ו-PING לזיהוי חיבור מת. הפירוט המלא ב-[PROTOCOL.md](PROTOCOL.md). הצפנה נוספת מתוכננת לגרסה 2.

### פרוטוקול OBEX
אין ב-Windows API ל-OBEX, ולכן מומש בתוכנה לקוח ושרת OBEX Object Push (פרופיל OPP, UUID `0x1105`) מעל RFCOMM:

- **קבלה:** `RfcommServiceProvider` עם שירות `ObexObjectPush`, `StreamSocketListener` והגנה `BluetoothEncryptionAllowNullAuthentication`.
- **שליחה:** `GetRfcommServicesForIdAsync` וחיבור עם `BluetoothEncryptionWithAuthentication`.
- **פרטי תאימות עם אנדרואיד שנלמדו בניסוי:**
  - יש להחזיר את הכותרת `ConnectionID` (`0xCB`) מתשובת ה-CONNECT.
  - החבילה הראשונה של PUT מכילה רק כותרות (`Name`, `Length`), בלי `Type` ובלי `Body`. אחריה חבילות `Body`, והאחרונה (`0x82`) כוללת `EndOfBody`.
  - קוד `0xCF` או `0xC0` משמעותם סוג או סיומת שנדחו, ואז עוטפים ב-ZIP.

### אבטחה
פתיחת ZIP היא הנקודה הרגישה ביותר, ולכן `SafeExtractor` מגן מפני:
- Zip-slip וניסיונות יציאה מהתיקייה (`..`, נתיבים מוחלטים).
- שמות שמורים של Windows (`CON`, `NUL` ודומיהם) ו-Alternate Data Streams (`:`).
- פצצות ZIP: מגבלות על גודל כולל, מספר קבצים ויחס דחיסה.
- דריסת קבצים: אף פעם לא דורסים, בוחרים שם ייחודי.

קבצים שהתקבלו מסומנים ב-Mark of the Web (`Zone.Identifier`), כך ש-Windows מתייחס אליהם כקבצים שהורדו מהאינטרנט. כל הבדיקות בקובץ [ArchiveTests.cs](tests/SendEasy.Tests/ArchiveTests.cs).

### פריט בתפריט הקליק הימני של Windows 11
- פריט ברמה העליונה דורש `IExplorerCommand` בחבילת MSIX. התוכנה היא שרת COM מחוץ לתהליך (`ExeServer`) בתוך `SendEasyBT.exe` (מצב `-Embedding`).
- החבילה דלילה (sparse): היא רק מצהירה על ההרחבה ומצביעה על הקבצים בתיקיית ההתקנה (`Add-AppxPackage -ExternalLocation`).
- החבילה חתומה בתעודה עצמית (`CN=SendEasyBT`) שנוספת ל-`LocalMachine\TrustedPeople`.
- כגיבוי: פריט רגיסטרי קלאסי (HKCU) ו-"שלח אל".

### מנגנונים נוספים
- **מופע יחיד:** Mutex ו-named pipe. נתיבים שמגיעים בתוך 700ms מאוחדים לחלון אחד.
- **קיצורי מקשים:** `RegisterHotKey`.
- **בחירה בסייר:** `Shell.Application` עם גיבוי של Ctrl+C ללוח.

### בנייה מהמקור
דרישות: Windows, .NET 8 SDK.

```powershell
dotnet build src/SendEasy.App -c Release
dotnet test tests/SendEasy.Tests
```

בניית מתקין מלא (חבילה חתומה והמתקין):

```powershell
dotnet restore build/fetch/buildtools.csproj
dotnet restore build/fetch/innosetup.csproj
./build/build_release.ps1
```
הסקריפט יוצר מפתח חתימה עצמי בתיקייה `keys/` אם אין, ושם נשמר המפתח הפרטי. התיקייה מוחרגת מ-git. **אל תפרסם את המפתח הפרטי.**

בניית אפליקציית האנדרואיד: JDK 17, Android SDK ו-Gradle 8.7.

```
cd android
gradle assembleDebug
```
ה-APK נוצר ב-`android/app/build/outputs/apk/debug/`.

### גרסאות אוטומטיות
תהליך GitHub Actions אחד ([build.yml](.github/workflows/build.yml)) רץ רק כשהקוד משתנה (`src/`, `tests/`, `build/`, `android/` או קובץ התהליך). שינויים ב-README או ברישיון לא מפעילים בנייה. הוא מריץ בדיקות, בונה את מתקין ה-Windows ואת ה-APK, ומפרסם Release אחד בתגית `v0.1.N` עם שני הקבצים (`SendEasyBT-Setup.exe` ו-`SendEasyBT.apk`) ומספר גרסה אחד. אם אחד מהם נכשל, לא מתפרסם Release. מפתח החתימה של ה-Windows נשמר כסוד של המאגר ואינו מופיע בקוד. ה-APK נחתם במפתח ה-debug הציבורי שבמאגר.
